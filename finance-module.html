Section A — Overview & Scope

This document is the single authoritative reference for the AIWS Finance Analytics build — budgeting, cash flow, working capital, profitability analysis, and strategic finance (prefix FI). It covers the 14 Finance Analytics features from the Excel Finance tab plus 2 features identified in the client's Finance Management Module PRD (FI-15, FI-16). Together these 16 features define the scope of the scale_finance custom app for Wave 1 (Sep 1 – Oct 10, 2026).

Companion document — Accounts Foundation

Core bookkeeping and statutory compliance (Chart of Accounts, AR/AP, Bank Reconciliation, GST, TDS/TCS, Fixed Assets, MIS Reports, and 15 other features) are scoped separately in accounts-module.html, under a dedicated scale_accounts app. Both apps are led by Uday; Accounts Foundation is scheduled first (Aug 1–29) since Finance Analytics depends on a working Chart of Accounts and Cost Centre tree. This split replaces an earlier version of this document that covered both scopes in one page — that version has been retired in favour of two focused plans.

How to navigate to the Finance module: Launch the bench → open your Scale site → click the Scale app launcher → find Scale Finance in the left sidebar. This entry appears after T00 (app creation) and bench migrate.

App: scale_finance (Python package name, git folder name, and ERPNext app name — all the same).  Platform: Frappe v15 + ERPNext v15 + Frappe Lending app (for FI-08 Loan Management). Depends on scale_accounts being installed first (Chart of Accounts, Cost Centre tree, GL).

Client PRD Analysis — 2 additional features identified (Finance Management Module PRD, Jul 2026)

The client Finance Management Module PRD contains 15 numbered feature sections plus a closing Executive Dashboard specification. 14 of the numbered sections align with the Excel Finance tab scope. The following 2 items appear in the client PRD but are not in the original Excel scope.

  • FI-15 — Profit Leakage Detection — AI-driven continuous monitoring of financial transactions to identify hidden losses, revenue leakages, margin erosion, and operational inefficiencies (Wave 2 · AI Build). Monitors: Excessive Discounts, Unauthorised Write-offs, Margin Erosion by product/customer, Abnormal Expense Spikes, Revenue Recognition gaps.
  • FI-16 — Executive Dashboard (CFO & CXO View) — a single real-time cockpit combining 16 KPIs pulled from across every Finance and Accounts feature: Revenue vs Budget, EBITDA, Net Profit, Cash Position, Working Capital, AR/AP, Budget Utilisation, Cash Flow Forecast, Loan & Liability Status, MSME Incentive Tracker, Product Profitability, Investment Performance, ROI by Initiative, Profit Leakage Alerts, AI Financial Risk Score, Top 10 AI Recommendations. The PRD gives this its own section, distinct from the per-feature reports each of FI-01 to FI-15 already produces. Phased: the 9 Wave-1-sourced KPIs ship with T10; the rest complete once Wave 2 AI builds and the Accounts module's own Executive Dashboard (AC-16) land.

All 14 Excel Finance features (FI-01 to FI-14) are in Wave 1 scope. FI-15 is Wave 2, assigned to Veeren (AI Head) as task V03. FI-16 is phased — Wave 1 partial (T10), Wave 2 complete (V07).

⚠ Note to AI Team

Do not modify any upstream Frappe/ERPNext source files. All custom logic lives exclusively inside apps/scale_finance/. Hook paths must use the outer Python package name only — e.g. scale_finance.msme_hooks.fn, never scale_finance.scale_finance.msme_hooks.fn. The inner scale_finance/scale_finance/ folder is the Frappe module for DocTypes and Workspaces, not for Python logic files.

  5. Commit the fixtures/custom_field.json file.

C.4 — How to Write a Python Hook (MSME 43B(h) enforcement)

# apps/scale_finance/scale_finance/msme_hooks.py

import frappe
from frappe.utils import date_diff, today, add_days

def flag_msme_payable(doc, method=None):
    """Flag Purchase Invoice if MSME supplier payment extends beyond 45 days (Section 43B(h))."""
    supplier = frappe.get_doc("Supplier", doc.supplier)
    if not supplier.get("scale_finance_msme_flag"):
        return
    due_date = doc.due_date
    if due_date and date_diff(due_date, doc.posting_date) > 45:
        doc.scale_finance_43b_risk_flag = 1
        frappe.msgprint(
            f"Section 43B(h) Alert: MSME supplier payment due beyond 45 days "
            f"(due {due_date}). Risk of tax disallowance.",
            alert=True, indicator="orange"
        )

Declare in hooks.py: "Purchase Invoice": {"before_submit": "scale_finance.msme_hooks.flag_msme_payable"}. After saving hooks.py, run bench restart — no migrate needed.

Phase 1 — Cost Centres & Budgeting (FI-01, FI-05)

OOTB FI-05 · Cost Centre Management & FI-01 · Budgeting ▶
⚠ Also scoped in Accounts module: FI-05 is the same underlying feature as AC-13 Cost Centre Accounting in accounts-module.html (Section D). The Excel workbook lists Cost Centres in both the Accounts and Finance tabs since it's foundational to both bookkeeping and analytics. Build it once — Cost Centre is a core ERPNext master (not app-specific data), so whichever app builds the tree first, the other consumes it automatically without any code. This document assumes it is built here (T01), before Accounts module's own Wave 1 window closes, since P&L and Budget dimensional reporting need it early. If Accounts module's team builds it first instead, skip the tree-creation step below and go straight to the Budgeting half.

Cost Centres — what already works: Native Cost Centre tree with parent-child hierarchy. Every transaction line item can be tagged to a Cost Centre. Financial Analytics report shows profitability per Cost Centre (Revenue vs Expense). Mandatory tagging can be enforced via Property Setter on journal entry fields.

Cost Centre configuration:

  • Build Cost Centre tree: Company Root → Sales / Marketing / HR / Finance / Operations / Manufacturing / Projects / each Branch — match the org chart exactly
  • Make Cost Centre mandatory on expense transactions: Customize Form on Journal Entry and Purchase Invoice → set "Cost Centre" field as Reqd via Property Setter → export fixture
  • Assign default Cost Centre per Department in Department master — auto-fills on transactions

Budgeting — what already works: Native Budget DocType links to Cost Centre + Account with monthly distribution. System enforces Stop/Warn/Ignore breach actions on Purchase Order, Purchase Invoice, and Journal Entry. Budget Variance report compares budgeted vs actual per Cost Centre and period.

Budget configuration:

  • Create Budget Distribution Template: allocate % per month (e.g. heavier Q4 for seasonal businesses)
  • Create annual budgets per Cost Centre × Account combination — this is a business task that Uday must coordinate with department heads
  • Set breach action: "Warn" for most cost centres (flag but allow), "Stop" for CapEx accounts (hard block over budget spending)
  • Configure Budget Approval Workflow: Budget Creator → Department Head → Finance Controller → CFO → MD
  • Test: raise a Purchase Order exceeding budget → verify warning appears → submit → verify GL shows overrun in variance report
Pre-work required: Annual budget figures by Cost Centre and GL account must be provided by department heads before T02. Block this task on data collection. Suggest Uday circulates a Budget Template Excel to each department head by Aug 25 for Sep 3 start.

Phase 2 — Cash Flow & Working Capital (FI-04, FI-07)

Partial FI-04 · Cash Flow Management ▶

What exists natively: Historical Cash Flow Statement (Operating/Investing/Financing) is a native ERPNext report — runs instantly from GL data. Bank balances and daily cash position are native (via Accounts module's Bank Reconciliation, AC-04). What does NOT exist: a forward-looking cash calendar (dues in vs dues out) or liquidity alerts.

What to build (T03):

  • Custom Script Report: 90-Day Cash Calendar — queries: open Sales Invoices (expected collections by due date), open Purchase Invoices (payments due), Loan EMI schedule (from FI-08), Payroll due dates, GST/TDS payment dates. Produces week-by-week projected cash position.
  • Daily cash position update hook: daily_cash_position_update() in tasks.py — fetches sum of all bank GL accounts → stores in a single-row Settings DocType for dashboard display
  • Alert: if projected cash drops below a configurable threshold within 7 days → email to CFO (Notification Rule)
  • Cash Calendar display: add as a Workspace Dashboard chart — bar chart by week (positive = net inflow, negative = net outflow)
  • AI integration point (Wave 2 — Veeren): feed historical collections data into LLM to predict actual collection probability per invoice (clients who pay late vs on-time pattern)
Partial FI-07 · Working Capital Management ▶

What exists natively: All underlying data exists — AR aging (DSO), AP aging (DPO), Stock Balance (Inventory Days) — but they live in separate reports. No unified Working Capital dashboard with metric dials.

What to build (T04):

  • Custom Script Report: Working Capital Dashboard — calculates: DSO (Receivables ÷ Revenue × 30), DPO (Payables ÷ COGS × 30), Inventory Days (Stock Value ÷ COGS × 30), Cash Conversion Cycle (DSO + Inventory Days – DPO), Working Capital Ratio (Current Assets ÷ Current Liabilities)
  • Add trend lines: compare each metric month-on-month (last 6 periods)
  • Alert thresholds: if DSO > 45 or CCC > 60 → auto-email Finance Controller with the metric details
  • Add to Scale Finance Workspace as a number card section so Uday sees the WC metrics on login

Phase 3 — P&L, Reporting, Variance, Segment Profit (FI-03, FI-06, FI-11, FI-12)

OOTB FI-03 · P&L Management & FI-06 · Financial Reporting ▶

What already works: Native P&L report, Balance Sheet, Cash Flow Statement, Trial Balance, General Ledger, Bank Book, Outstanding Reports — all available the moment CoA is mapped and transactions are posted (Accounts module, AC-01). All reports support period filters, cost centre filters, and export to Excel/PDF. Accounting Dimensions allow segmented reporting by Project, Location, Branch, or any custom dimension.

What to configure (T05):

  • Configure Accounting Dimensions: Add "Branch" and "Business Unit" as dimensions in Accounts Settings → these become filter options on all financial reports
  • Set up Comparative P&L: verify Current vs Previous Year comparison works after first FY of data
  • Build Customer P&L: use Financial Analytics filtered by Party = Customer (shows revenue + expenses attributable to that customer)
  • Configure Product-level P&L: use Gross Profit report filtered by Item Group → gives revenue and COGS per product category
  • Pin most-used reports to Scale Finance Workspace as Quick Links
  • Test Budget vs Actual view: open P&L → enable "Show Budget" toggle → verify against budgets created in T02
OOTB FI-11 · Profit by Product / Segment & FI-12 · Variance Analysis ▶

Profit by Segment — what already works: Native Gross Profit report calculates (Selling Price – Stock Valuation Rate) per Item/Item Group/Customer. Supports filtering by date range, Item Group, Customer Group. Drillable to source Sales Invoice.

What to configure (T06):

  • Ensure stock valuation method is correct (FIFO or Moving Average — set at Item level) — wrong method gives wrong Gross Profit
  • Map Item Groups to match the client's product categories: run the Gross Profit report by Item Group → share with Uday for validation
  • For indirect cost allocation (attributing overheads to products): use Accounting Dimensions — tag overhead invoices to the same dimension as the product revenue, then use Financial Analytics to get a fully loaded P&L per segment
  • Build Product Profitability dashboard: top 10 and bottom 10 items by Gross Margin % (Script Report)

Variance Analysis — what already works: Native Budget Variance Report compares Budget vs Actual per Cost Centre and account, monthly and cumulative. No custom build needed.

What to configure:

  • Budget Variance Report: filter by Cost Centre → date range → compare to budget. Works as-is once T02 budgets are loaded.
  • Configure weekly Variance Summary email: weekly_budget_variance_summary() in tasks.py → runs every Monday → emails Cost Centres that are >10% over budget
  • Enable Forecast vs Actual comparison once FI-02 forecasting is built (Wave 2)

Phase 4 — Loans, MSME, Investment (FI-08, FI-09, FI-10)

App Install FI-08 · Loan & Liability Tracking ▶

What exists natively (without Frappe Lending): Loans can be tracked as GL entries only — manual JE for receipt, interest accrual, and EMI. No EMI schedule, no outstanding balance tracking, no maturity alerts. Frappe Lending app provides full loan lifecycle.

What to install and configure (T07):

  • Install Frappe Lending: bench get-app lending → bench --site <site> install-app lending → bench migrate
  • Create Loan Types: Term Loan (reducing balance), OD/CC Account (revolving), Equipment Finance (fixed EMI)
  • For each active loan: create Loan document with principal, interest rate, disbursement date, tenure, EMI amount — system generates full amortisation schedule
  • Map loan GL accounts: Loan account → Balance Sheet Liability sub-head, Interest expense → P&L Finance Costs sub-head
  • Configure daily EMI alert: daily_loan_emi_alert() in tasks.py → checks EMI due within 3 days → emails Finance team
  • Statutory Liabilities (GST, TDS, PF payable): these are tracked via the GL liability accounts created in the Accounts module (AC-01) — no custom DocType needed
  • Delay Risk — High: Frappe Lending requires detailed loan data (sanction letters, disbursement dates, original schedules) from the client. Get all active loan schedules from Uday before T07.
Custom FI-09 · MSME Scheme Tracking ▶

What exists natively: Nothing — no ERP ships MSME scheme tracking. This is a high-value, India-specific custom build. Two distinct sub-features: (a) MSME supplier payment rule enforcement (Section 43B(h) — 45-day payment limit), and (b) Government scheme/subsidy tracking for the company itself.

What to build (T08):

  • Section 43B(h) enforcement: Custom fields on Supplier (scale_finance_msme_flag Check, scale_finance_msme_reg_no Data). Hook on Purchase Invoice before_submit: if MSME supplier and payment due > 45 days, set risk flag and alert Finance team. Daily task: daily_msme_overdue_check() — checks all open MSME invoices past 45 days → escalation email to Finance Controller.
  • Script Report: MSME 43B(h) Overdue Register — lists all MSME supplier invoices overdue > 45 days with supplier name, invoice amount, due date, overdue days — required for year-end tax reconciliation.
  • MSME Scheme DocType: Fields: Scheme Name (Data), Scheme Type (Select: Subsidy / Tax Incentive / Export Incentive / Credit Guarantee / Skill Development), Eligibility Criteria (Long Text), Application Status (Select: Eligible / Applied / Approved / Received / Expired), Benefit Value (Currency), Application Date, Approval Date, Renewal Date, Required Documents (Table: document name, submitted checkbox). Add alerts via Notification on Renewal Date approaching 30 days.
  • AI task (Veeren Wave 2): prompt LLM with company profile (industry, turnover, employees, export %) → recommend applicable MSME schemes from a curated scheme database
Custom FI-10 · Investment Planning ▶

What exists natively: Investments are tracked as GL entries under the Assets group. No maturity tracking, no renewal alerts, no ROI calculation, no portfolio view. Small, high-value custom DocType.

What to build (T09):

  • Custom DocType: Investment Register — Fields: Investment Name (Data), Investment Type (Select: Fixed Deposit / Mutual Fund / Bonds / Equipment Finance / Business Expansion / Technology / Other), Institution (Data), Amount Invested (Currency), Date of Investment (Date), Maturity Date (Date), Expected Return % (Float), Expected Maturity Amount (Currency), Actual Return (Currency), Status (Select: Active / Matured / Withdrawn / Defaulted), GL Account (Link to Account), Risk Level (Select: Low / Medium / High), Notes (Text)
  • Weekly maturity alert: weekly_investment_maturity_check() in tasks.py → checks investments maturing within 30 days → emails Uday + CFO with details
  • Investment Portfolio Script Report: summary by type (FD vs MF vs Bonds), total corpus, maturity schedule for next 12 months, IRR calculation
  • Link to CapEx approval: for Plant/Machinery investments > ₹10 lakh, require approval Workflow: Finance Lead → CFO → MD
Phased · Client PRD FI-16 · Executive Dashboard (CFO & CXO View) ▶
⚠ Also scoped in Accounts module: The Accounts Management Module PDR independently specifies its own AC-16 Executive Dashboard with an overlapping but not identical KPI list (15 accounting-centric KPIs vs this feature's 16 finance-centric KPIs — see accounts-module.html Section D). Do not build two separate dashboards — Uday's team should decide one home (recommended: build the merged KPI set here in scale_finance, since it already depends on both apps' data, and have the Accounts workspace link to it) before starting T10.

Client PRD objective: A single real-time dashboard giving CFO/CXO leadership a consolidated view across every Finance feature, rather than navigating 15 separate reports. The PRD lists 16 specific KPIs: Revenue vs Budget, EBITDA, Net Profit, Cash Position, Working Capital, AR/AP, Budget Utilisation, Cash Flow Forecast, Loan & Liability Status, MSME Incentive Tracker, Product Profitability, Investment Performance, ROI by Initiative, Profit Leakage Alerts, AI Financial Risk Score, Top 10 AI Recommendations.

  • Cash Position, Cash Flow Forecast — from FI-04 cash flow hooks
  • Working Capital — from FI-07 dashboard
  • Loan & Liability Status — from FI-08 Frappe Lending
  • MSME Incentive Tracker — from FI-09 MSME Scheme DocType

Wave 2 Features — Custom AI Builds (FI-02, FI-13, FI-14, FI-15, FI-16 Phase 2)

These features require custom AI builds or complex Script Reports. They depend on Wave 1 data being stable (at least 3 months of clean transactions). Assigned to Veeren (AI) and Dev2 for Nov 2026+.

Wave 2 FI-02 · Financial Forecasting ▶

Client PRD objective: Predict future financial performance using historical data, seasonality, and AI. Forecast: Revenue, Expenses, Profit, Cash Flow, Working Capital, Collections, Payments, Inventory Value, EBITDA, Net Profit. Periods: Weekly, Monthly, Quarterly, Annual, Three-Year. Models: Manual, Statistical, AI Prediction, Scenario Planning (Best/Expected/Worst case).

What ERPNext provides: Payment schedules and open order book are native data sources. Rolling forecast or scenario modeling does not exist natively.

Wave 2 approach (Veeren):

  • Data foundation (build in Wave 1): ensure GL, AR/AP, Payroll, and Stock data are clean for 3+ months
  • Custom Script Report: Rolling Revenue Forecast — uses confirmed order book (open Sales Orders) + historical conversion rates + seasonal adjustment → projects next 90-day revenue
  • AI Forecasting engine: weekly batch job → gathers 12-month GL history → calls LLM/statistical model → generates Best/Expected/Worst case P&L → stores in a Forecast Entry DocType → displays as chart in Finance workspace
  • Scenario Planning: allow Finance team to input assumptions (revenue growth %, cost increase %) → system recalculates projected P&L and Cash Flow interactively
  • Pre-work for Wave 2: Uday defines the KPIs and scenarios relevant to the business. Without this, the AI model has no objective to optimise for.
Wave 2 FI-13 · Break-even Analysis ▶

Client PRD objective: Calculate Fixed Costs, Variable Cost per Unit, Contribution Margin, Break-even Units/Revenue, Margin of Safety. Support by Product, Business Unit, Branch, Project. AI: recommend selling price adjustments, predict break-even timelines.

What ERPNext provides: Gross Profit report gives Revenue and COGS per item. P&L provides overhead totals. But fixed vs variable cost tagging does not exist — this must be configured first.

Wave 2 approach:

  • Phase 1 — Cost tagging: add custom field scale_finance_cost_nature (Select: Fixed / Variable / Semi-variable) on Account DocType → Uday tags all expense GL accounts accordingly → export fixture
  • Phase 2 — Break-even Script Report: (Fixed Costs ÷ (Selling Price – Variable Cost per Unit)) per product. Pulls: fixed costs from GL filtered by fixed accounts, variable costs from COGS in Gross Profit report, selling price from Item master
  • Break-even Dashboard: SVG chart showing Revenue line vs Total Cost line, break-even point highlighted, margin of safety shaded
  • AI (Veeren Wave 2): simulate price change → recalculate break-even → recommend minimum viable price
Wave 2 FI-14 · ROI Tracking ▶

Client PRD objective: Track ROI for: Marketing Campaigns, Projects, CapEx, Machinery, Software, Employee Training, Business Expansion. Metrics: Investment Amount, Revenue Generated, Cost Savings, Net Benefit, ROI %, Payback Period. AI: predict expected ROI, benchmark across initiatives, recommend underperforming project termination.

Wave 2 approach:

  • Custom DocType: ROI Tracker — Fields: Initiative Name, Category (Select: Marketing / CapEx / Technology / Training / Expansion / Other), Investment Amount, Start Date, Expected Returns Date, Revenue Generated (Currency, updated periodically), Cost Savings (Currency), Net Benefit (formula field), ROI % (formula), Payback Period (formula), Status (Active / Monitoring / Closed), Linked Asset / Project / Campaign
  • Link Marketing ROI to CRM Campaign DocType (from scale_sales) — pull actual revenue attributable to campaign
  • Link CapEx ROI to Fixed Asset (from Accounts module AC-10) — pull depreciation + associated revenue stream
  • ROI Dashboard Script Report: ranked list of all initiatives by ROI %, traffic-light status (green >20%, amber 5–20%, red <5%)
  • AI (Veeren Wave 2): weekly scan of underperforming initiatives (ROI < threshold after 6 months) → LLM generates termination recommendation with rationale
Wave 2 · Client PRD FI-15 · Profit Leakage Detection ▶

Client PRD objective: Use AI to continuously monitor financial transactions and operational processes to identify hidden losses, revenue leakages, margin erosion, and operational inefficiencies. Monitor: Excessive Discounts, Unauthorised Write-offs, Margin Erosion, Abnormal Expense Spikes, Revenue Recognition Gaps, Under-invoicing, Over-payment to suppliers.

What ERPNext provides: All transaction data exists in GL, AR/AP, Sales/Purchase Invoices. What's missing is pattern recognition across those datasets — this is an AI task.

Wave 2 approach (Veeren):

  • Daily scan function: ai_leakage_scan() in ai_utils.py — queries GL for last 24 hours of transactions → aggregates by vendor/customer/item → detects anomalies (discount % above threshold, unit price below floor, single vendor payment spike > 2σ from mean)
  • Custom DocType: Profit Leakage Alert — Fields: Alert Date, Category (Excessive Discount / Margin Erosion / Expense Spike / Revenue Gap), Transaction Reference, Expected Amount, Actual Amount, Variance %, AI Explanation (Long Text generated by LLM), Status (New / Under Review / Resolved / False Positive)
  • Threshold config: store alert thresholds in a Settings DocType (e.g. discount alert if > 15%, expense spike if > 50% above 90-day average)
  • Weekly Leakage Report email to CFO: summary of all new alerts in the past week with estimated financial impact
  • Pre-work for Wave 2: Uday defines acceptable thresholds per category. AI needs a baseline of 3+ months clean data before anomaly detection is meaningful.
