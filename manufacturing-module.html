Manufacturing Module — Implementation Plan

Production for scale_manufacturing (client scope tab name: "Production"). Build started — Phase 1 (BOM/Work Order/consumption/output) confirmed live, third of the three new Supply Chain modules as planned, since it depends on both Stores and Purchase & Procurement (both now done) — its own spec remains the least mature of the three, with Phase 2's custom pieces still waiting on the missing PRD.

Open gap, flagged before any build starts: Unlike Purchase, there is no dedicated client PRD for Manufacturing in Claude/reference_from_team/ — only the one-line-per-feature "Production" tab in the Excel scope sheet (15 features, description + AI-enablement flag, no functional-requirements depth, no field lists, no report names). Per this project's own working rule ("verify against source PDFs/Excel — never build from a thin description if a real PRD should exist"), request a proper Manufacturing/Production PRD from the client or SIL team before Phase 2's custom pieces are built — Phase 1 (native BOM/Work Order/Job Card configuration) can safely start from the Excel description alone since it's ERPNext's best-covered native module (83% OOTB per module-plan.html's own estimate).

App: scale_manufacturing, own app, required_apps = [..., "scale_stock", "scale_purchase"] — needs both (BOM needs Items from Stores; MRP shortfalls raise Purchase Requests).

Why Manufacturing goes third: Its own scope sheet says so directly — Work Orders need Items (Stores) and Production Planning's MRP raises material shortfalls as Purchase Requests (Purchase). Building it last also buys time to get the missing PRD, so the custom pieces (Phase 2/3 below) are specified properly instead of guessed from one-line descriptions.

Module Objective

Turn a Bill of Materials and a sales/forecast demand signal into finished goods on the shelf — with raw-material consumption, machine/labour time, and scrap all costed accurately, and no work order started without knowing whether material and capacity actually exist.

Phase-by-Phase Implementation

Three phases following the make-to-stock flow. Phase 1 is the BOM→Work Order→consumption→output backbone. Phase 2 is quality/costing/capacity governance. Phase 3 is scheduling/reporting polish. Do not start Phase 2's custom pieces until the missing PRD (see banner above) is obtained — Phase 1 is safe to start on the Excel description alone since it's near-100% native configuration.

Phase 1 — Make-to-Stock Backbone

OOTB MFG-01 · Bill of Materials ▶

What already works: Multi-level, costed BOMs; ERPNext v16 Phantom BOMs for pass-through sub-assemblies that shouldn't be stocked as an intermediate item.

What to add: Nothing structural — this is pure master-data setup once Item master (Stores STR-01) exists. Confirm with the client whether Phantom BOM applies to any of their sub-assemblies before building the BOM tree.

OOTB MFG-02 · Process Routing ▶

What already works: Native Routing defines the operation sequence, workstations, and standard times — reused across products via BOM linkage.

What to add: Configuration only — build the actual routing templates from the client's real process once obtained (this is part of the missing-PRD gap: routing detail needs the client's actual operation sequence, not assumptions).

OOTB MFG-03 · Work Orders ▶

What already works: Full lifecycle with material binding and per-operation Job Cards at workstations.

Depends on: BOM (MFG-01) and Item/Warehouse (Stores STR-01/02) must exist first.

OOTB MFG-04 · Raw Material Consumption ▶

What already works: Transfer-for-manufacture and consumption entries against the Work Order, recorded at the moment they happen — same Stock Entry mechanism Stores already configures (STR-04).

OOTB MFG-05 · Finished Goods Output ▶

What already works: Manufacture Receipt brings FG into stock with batch/serial and true cost in one motion, closing the loop back into the same Stock Ledger Stores owns.

Phase 2 — Quality, Costing & Capacity Governance

OOTB MFG-06 · Quality Control ▶

What already works: Quality Inspection with templates for incoming (feeds Purchase's GRN), in-process (via Job Card), and outgoing inspection.

Needs from client (missing PRD gap): actual inspection parameters/templates per product line — not specified in the Excel one-liner.

OOTB MFG-07 · Batch / Job Costing ▶

What already works: Work Order costing — actual materials + operation time at workstation rates, with variance vs. standard cost visible natively.

Refine MFG-08 · Capacity Planning ▶

What already works: Workstation capacity is native.

What to add: A load-vs-capacity view and a pre-commitment "do we actually have the hours?" check before a Work Order is released — likely a Script Report over native Workstation/Job Card data, not a new DocType.

OOTB MFG-09 · Sub-contracting ▶

What already works: ERPNext's revamped subcontracting flow — material sent to vendor, finished parts received back, costs reconciled. Ties directly into Purchase's Supplier/PO flow for the vendor side.

Phase 3 — Scheduling & Reporting Polish

Refine MFG-10 · Machine Scheduling ▶

What already works: Workstations + Job Card scheduling are native.

What to add: A visual scheduling board with finite capacity — the one genuinely new UI piece in this module (comparable in shape to PMO's Gantt work). Scope depth depends on the missing PRD.

OOTB MFG-11 · Downtime Tracking ▶

What already works: Downtime Entry linked to workstation/Job Card with reason codes, feeding availability & OEE analysis natively.

OOTB MFG-12 · Scrap & Waste Management ▶

What already works: Scrap items in BOM plus process-loss accounting — waste is costed automatically, not a manual write-off.

Refine MFG-13 · Shift Management ▶

What already works: Shift types are native, shared with HR.

What to add: Shift-wise output/OEE reporting and handover notes — the Production-specific extension on top of HR's native shift master.

Refine MFG-14 · Production Reports ▶

What already works: Native operational reports.

What to add: Plan-vs-actual, OEE trends, and exception views — assembled in the shared Dashboards module (Wave 4), same pattern as every other module's analytics.

OOTB MFG-15 · Production Planning (MRP) ▶

What already works: Production Plan built from Sales Orders or forecast, with MRP — material shortfalls become Purchase Requests automatically. This is the direct integration point into Purchase's Inventory Procurement Planning (PUR-13).

Sequenced last in Phase 1's logical flow (numbered 15, not 6, in the build list) because it's the one feature that needs BOM, Work Order, and a working Purchase Requisition flow (PUR-01) all in place before it can be tested end-to-end — it's the integration proof point across all three new modules, not a standalone config task.

Task List

One task per feature, in build order. No dates assigned yet (see Open Decisions) — and several tasks below are explicitly blocked on the missing PRD, not just on lead assignment.

MFG-01

BOM setup

✅ Done
Effort: Medium · Depends on: Stores STR-01 (Item master)

Confirmed live with a real 2-level BOM (raw material → sub-assembly → finished good): multi-level cost roll-up correctly propagated through both levels (a sub-assembly costed via its own submitted BOM was picked up automatically when costing the parent). Real correction to the plan, found while testing: "ERPNext v16 Phantom BOM" (pass-through sub-assemblies that skip stocking an intermediate item) does not exist on this bench's actual ERPNext version (15.118.1) — grepped the entire manufacturing module for "phantom," zero hits anywhere. If the client genuinely needs it, that's a version upgrade, not something this app can add on top. Also confirmed native BOM costing reads from an item's actual valuation history ("Rate Of Materials Based On" defaults to Valuation Rate, no "Manual" option exists on this version) — a brand-new item needs a real opening stock transaction before its BOM cost will show anything other than zero, not just a typed-in rate.

MFG-02

Process Routing setup

⏸ Blocked on PRD
Effort: Medium · Blocked on PRD — needs client's real operation sequence

Not started, not skipped by accident — the native Routing/Operation mechanism itself is confirmed native (same as every other Phase 1 piece), but building real templates needs the client's actual process sequence, which doesn't exist in any source document yet (see the module's own open-gap banner above).

MFG-03

Work Order configuration

✅ Done
Effort: Low · Depends on: MFG-01, MFG-02

Confirmed live against the same 2-level BOM used for MFG-01: Work Order's own required_items correctly explodes all the way down to the raw-material level (6 units of raw steel for 1 finished good needing 3 sub-assemblies × 2 raw each), not just the immediate sub-assembly — multi-level BOM support holds at the Work Order layer too, not only in BOM costing. Didn't end up depending on MFG-02 in practice, since a Work Order can be raised and worked without a Routing attached (Routing only matters once operation-level Job Cards are needed).

MFG-04

Open Decisions

Request a Manufacturing/Production PRD

The single biggest open item for this module. Purchase & Procurement had a 15-page PRD; Stores had a fully fit-gap-annotated Excel tab; Production has neither. Routing (MFG-02), Quality Inspection templates (MFG-06), and the Machine Scheduling board's real scope (MFG-10) all need it before Phase 2 custom work should start.

Lead & start date not yet assigned

Same as Stores/Purchase — Wave 2, Lead: TBD in module-plan.html. Given the dependency chain, Manufacturing's real start date should trail Stores/Purchase's, not run in strict parallel with them.
