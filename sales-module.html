Module Objective

The Sales Management Module provides complete visibility into the sales lifecycle — from lead generation to revenue collection — while enabling sales teams to improve productivity and helping leadership make timely, data-driven decisions. It must ensure: every opportunity is tracked, no lead is lost, sales forecasting is reliable, activities are monitored, collections are visible, and AI continuously recommends actions to improve performance.

Client Script — GPS Check-In button (25 lines)
frappe.ui.form.on('Field Visit', {
  refresh(frm) {
    if (!frm.doc.check_in_time) {
      frm.add_custom_button('Check In', () => {
        if (!navigator.geolocation) {
          frappe.throw('Geolocation not supported on this device.');
          return;
        }
        navigator.geolocation.getCurrentPosition(pos => {
          frm.set_value('latitude', pos.coords.latitude);
          frm.set_value('longitude', pos.coords.longitude);
          frm.set_value('check_in_time', frappe.datetime.now_time());
          frm.save();
          frappe.show_alert({ message: 'Checked in!', indicator: 'green' });
        }, () => {
          frappe.throw('Could not get location. Allow location access in your browser.');
        });
      }).addClass('btn-success');
    } else if (!frm.doc.check_out_time) {
      frm.add_custom_button('Check Out', () => {
        frm.set_value('check_out_time', frappe.datetime.now_time());
        frm.save();
      }).addClass('btn-warning');
    }
  }
});
Custom SALES-07 · Distributor Management Built Differently ▶

Originally planned approach: Two new DocTypes inside scale_sales, plus a Frappe Workflow for claim approval.

  • DocType: Secondary Sales Entry — links to Customer (Group=Distributor), stores period, product list, secondary off-take quantity and value. Used for monthly distributor sales uploads.
  • DocType: Distributor Claim — scheme name, claim amount, supporting docs, workflow states: Draft → Submitted → Under Review → Approved / Rejected. Approval triggers Journal Entry.
  • Script Report: Distributor Health Dashboard — primary sales (from Sales Invoice), secondary sales (from Secondary Sales Entry), outstanding, last visit date, claim status.

What actually got built (Muhammad, PR #8, merged 7 Aug 2026): a single Distributor Onboarding DocType instead — the intake/application side of this feature, not the ongoing operations side above. Status pipeline: Draft → Documents Pending → Under Review → Approved/Rejected → Active. On reaching Approved or Active, approved_by/approved_on auto-stamp; on Approved with a linked Customer, Customer Group is set to Distributor automatically (verified in code — matches the description exactly). Territory, Sales Person, Payment Terms, and a documents checklist are on the form. Secondary Sales Entry, Distributor Claim, and the Health Dashboard report — the actual ongoing-operations half of this feature — were not built. Not a bug or a missed step; this PR's scope was distributor onboarding specifically, and the broader operations tooling remains open work.

Custom SALES-12 · Sales Incentive Management ▶

Approach: One DocType for scheme rules, one Python script for calculation, one report for output. All inside scale_sales.

  • DocType: Sales Incentive Scheme — Incentive Type (Monthly/Quarterly/Annual), Target Metric (Revenue/Collections/Volume), Slab Table (from % → to % → payout %), effective from/to dates, applicable Sales Person.

  • Script Report: Incentive Payout Summary — rep-wise payout amounts, achievement %, approval status, link to payroll push.

Phase 3 — Pipeline & Forecasting (Aug 21 – Sep 15)

OOTB SALES-03 · Sales Pipeline (10-stage Kanban) ▶

10 Pipeline stages to configure in CRM Settings: Lead → Qualified → Discovery → Presentation → Proposal → Negotiation → Commercial Discussion → Purchase Decision → Won → Lost

Each stage has a default Probability %. Stage probability drives weighted revenue in forecasting.

  • Child table on Opportunity: Opportunity Stakeholder — Name, Title, Influence (Decision Maker / Influencer / User), Email
  • Child table on Opportunity: Opportunity Competitor — Competitor Name, Our Advantage, Their Advantage, Price Difference %
  • Client Script: auto-set Probability % when stage changes
  • Stale Deal alert: Server Script flags Opportunities with no activity in 7 days
Script SALES-04 · Sales Forecasting ▶

Approach: Native Frappe Script Report — no separate forecasting app. Python queries active Opportunities and computes Weighted Revenue = Σ(Opportunity Amount × Stage Probability %).

Report buckets: Committed (stage ≥ 70%), Best Case (40–69%), Pipeline (rest). Compares against Sales Target for the period. Highlights revenue gap.

frappe.ui.form.on('Field Visit', {
  refresh(frm) {
    // Show Check-In button only if not yet checked in
    if (!frm.doc.check_in_time) {
      frm.add_custom_button(__('Check In (GPS)'), () => {

Server Script — Lead Duplicate Detection
import frappe

def execute():
    if not (doc.mobile_no or doc.email_id):
        return  # can't deduplicate without contact info

    filters = []
    if doc.mobile_no:
        filters.append(['mobile_no', '=', doc.mobile_no])
    if doc.email_id:
        filters.append(['email_id', '=', doc.email_id])

    for f in filters:
        existing = frappe.db.get_all('Lead',
            filters=[f, ['name', '!=', doc.name or '']],
            fields=['name', 'lead_name', 'status'],
            limit=1

        if existing:

            frappe.throw(
                f"A Lead already exists with this contact: "
                f"<a href='/app/lead/{lead.name}'>{lead.lead_name}</a> "
                f"(Status: {lead.status}). "
                f"Please open and update that record instead.",

V03 SALES-20 · NL Query — Production Endpoint (ai_query.py) Veeren Wed 30 Jul · Est. 1 day · ⭐ PRIORITY

  1. Create apps/scale_sales/scale_sales/api/ai_query.py with a whitelisted function: 
    import frappe
from scale_sales.scale_sales.ai_utils import call_llm
from scale_sales.scale_sales.ai_query_schema import SALES_SCHEMA

ALLOWED_DOCTYPES = {"Lead", "Opportunity", "Customer", "Sales Invoice", "Field Visit", "Sales Order"}

@frappe.whitelist()
def answer(question: str) -> str:
    """Natural language query answerer for Sales & Marketing data."""
    # Step 1: Ask LLM to translate question to frappe.get_list call
    translate_prompt = f"""You are a Frappe ERPNext query assistant. Given a question,
return ONLY a Python dict representing arguments to frappe.get_list().
Schema: {SALES_SCHEMA}
Question: {question}
Return format: {{"doctype": "...", "filters": [...], "fields": [...], "limit": N}}
Return ONLY the dict, no explanation."""

    raw_query = call_llm(translate_prompt)

    # Step 2: Parse and validate the query
    import json, ast
    try:
        query_args = ast.literal_eval(raw_query)
        assert query_args.get("doctype") in ALLOWED_DOCTYPES
    except Exception:
        return "I could not understand that question. Try rephrasing it."

    # Step 3: Execute safely
    results = frappe.get_list(**query_args)

    # Step 4: Ask LLM to format results as plain English
    format_prompt = f"""The user asked: "{question}"
The database returned: {results}
Write a clear, concise answer in 1-3 sentences. Use numbers. Be specific."""

    return call_llm(format_prompt)
