Section A — Overview & Scope

This document is the single authoritative reference for the AIWS Project Management Office (PMO) module build — project planning, budgeting, resourcing, tasks, milestones, risk, change control, timesheets, billing, and the AI layer that turns raw execution data into delay/budget/resource foresight. It reconciles two source documents that do not describe the same scope (see the fidelity note directly below) into one build list of 20 features.

⚠ Fidelity check: the PRD and the Excel tab scope different things

Per the standing rule to verify against source documents directly rather than trust a skim: the 17-page Project Management Module.pdf and the Excel workbook's "Project Management Office" tab were read in full this session, independently, and cross-checked term by term. They overlap on roughly half their content and diverge meaningfully on the other half:

  • The PDF is a 10-section functional PRD (Planning, Budget, Resource, Task, Milestone, Risk, Timesheet, + 3 dedicated AI sections: Delay Prediction, Resource Optimization, Budget Forecasting) plus a closing Executive Dashboard spec. It is ERP-agnostic — it never mentions Frappe or ERPNext.
  • The Excel tab is the business's own Frappe-feasibility-scored build list — 14 numbered rows (one was a flagged duplicate, discarded per Decision 1 below), each already annotated with what's native, what's custom, and a standard flow. This is the same tab format used for Sales/Accounts/Finance and is the authoritative "what to build" list per project convention.
  • The two lists are not the same 13–14 things phrased differently. The Excel tab covers onboarding (Project/Consultant/Client), Calendar, Task, Timesheet, Invoicing, a Cockpit Dashboard, Gantt, Risk, Change Management, Impact Report, and Library — largely operational/administrative PMO functions. The PDF's Resource Management section (§3 — a full chapter: employee/consultant/contractor/machine/vehicle/tool allocation, utilization %, capacity, skill matching, resource booking/transfer/replacement) has no corresponding Excel row at all — the closest the Excel tab gets is a "weekly availability planner" buried inside Consultant Onboarding. Likewise the PDF's full multi-category Budget Management chapter (§2 — 7 cost categories, a 4-level approval chain, budget-vs-actual-vs-forecast tracking) is only thinly represented in Excel row 1.0 as "role-based manday & cost budgets." And the PDF's three dedicated AI chapters (§8–10) aren't scoped as distinct Excel rows at all — Excel just flags "AI Enablement: Yes" generically on every row.

This page does not silently pick one source over the other. All 13 Excel-tab features are in scope as PMO-01 to PMO-13. The PDF-only gaps that a modern PMO platform genuinely needs — and that ERPNext does not cover natively — are added as PMO-14 to PMO-20 below, clearly labeled as recommended additions rather than business-confirmed scope, per the instruction to flag exactly this kind of gap.

PMO Feature Breakdown

Group 1 — Onboarding (PMO-01, 02, 03)

Partial PMO-01 · Project Onboarding ▶

What already works: Project and Project Template are native ERPNext DocTypes — a template with a predefined task hierarchy can be instantiated into a new project, auto-generating tasks. Confirmed directly against the ERPNext source: Project has project_name, status, project_type, expected_start_date/end_date, priority, department, customer, estimated_costing, and a users child table for team assignment — all native.

What we need to build: A Kickoff Checklist child table on Project. Role-based manday & cost budget fields per project role (feeds PMO-15). A PMO Director sign-off workflow (Draft → Kickoff Pending → PMO Approved → Active) — native ERPNext has no such initiation gate; Project.status is a plain Select field, not a workflow. A Project Initiation PDF print format.

Fields the PDF asks for that Project doesn't natively have: Project Code (separate from name), Sponsor, Contract Value, Success Criteria, Scope, Objectives — straightforward Custom Fields, no schema conflict. Add a Methodology Select field (Waterfall/Agile/Hybrid/Scrum/Kanban per the PDF) — a plain field, not a workflow engine change; native Kanban/Gantt views already exist regardless of which value is picked.

WBS, Phases, Deliverables — addressed via existing structures, not new DocTypes: the PDF asks for Work Breakdown Structure, Project Phases, and Deliverables as first-class Planning concepts. WBS and Phases are achievable with native Task's parent_task/is_group tree — a Phase is just a group-Task one level under the Project — so no new DocType is needed, only a convention (documented in the developer guide) that top-level group Tasks represent Phases. Deliverables has no equivalent anywhere — Project has no Deliverables field or child table today. Add a Deliverables child table on Project (Title, Due Date, Owner, Status) — this also directly feeds PMO-16 Milestone Management, which needs Deliverables at the milestone level too.

Partial PMO-16 · Milestone Management Gap-identified ▶

Why this is here even though it's not an Excel row: The PDF gives Milestone Management its own full chapter (§5) — Milestone Name, Planned Date, Actual Date, Deliverables, Dependencies, Approval Required, and a Completed/Delayed/Upcoming status view with its own dashboard and variance report. Task does have an is_milestone checkbox natively, confirmed in the schema — but that's a flag on a Task, not a first-class trackable entity with its own dashboard, approval gate, or variance reporting.

Recommendation: Don't build a separate Milestone DocType — that would fragment data away from Task, which already carries dependencies and dates. Instead build a Milestone Dashboard that filters Task where is_milestone = 1, adds the missing approval_required and deliverables (child table, reusing PMO-01's Deliverables structure) custom fields and an approval action, and produces the Completed/Delayed/Upcoming view and variance report the PDF asks for — all as a thin custom layer over the existing Task data, not a new source of truth.

Reports (PDF §5): Milestone Dashboard and Milestone Variance are this feature's own deliverables (above). Timeline Report is a third, separate ask — a flat chronological list of all milestones across active projects, distinct from the Gantt (PMO-09, which is per-project) and the Dashboard (which is status-grouped, not date-ordered).
