🎬 Client Demo Story

Apex Manufacturing Co — The Pump Assembly A1 Bulk Order

Every module demo before this ran on its own disconnected test data — Stock, Purchase, Manufacturing, HR, PMO each told a different, unrelated story, so nobody watching could see how a real order actually moves through the system. This is the fix: one realistic manufacturing project, seeded consistently across every module using nothing but Scale's own native project linking — click from the Project record straight into the real Sales Order, BOM, Work Order, Purchase Order, and Payment that belong to it.

1 The Story

Apex Manufacturing Co, an existing industrial customer, places a bulk order for 250 units of Pump Assembly A1 — a precision pump used in their water-treatment line expansion. Fulfilling it touches every part of the business: Sales books the order, PMO runs it as a real project with its own risks and budget, Manufacturing builds a Bill of Materials and runs it through Production Planning to see what's short, Purchase closes that shortfall with a new supplier, and Stock receives, tracks, and feeds the raw material back into production.

Every record below is real and already live on this bench — not mocked, not a slide. The project is PROJ-0025 · Apex Manufacturing — Pump Assembly A1 Bulk Order, and every module's data is tagged to it the same way ERPNext tags any project-linked transaction — which is what makes the Connections tab on the Project record able to show all of it in one place, natively, with nothing custom built to make it work.

2 The Flow, Module by Module

PMO (the hub). The Project is created first — customer Apex Manufacturing Co, a Project Manager and 2-person team from the existing HR roster, four Tasks (Procure → Produce → QC → Dispatch), a Project Risk flagging steel price volatility, a Timesheet entry, and an Expense Claim for a supplier quality audit visit.

Sales. A Quotation for 250 units is raised, walked through Sales' own discount-approval workflow, and converted into a real Sales Order — the commercial trigger for everything downstream.

Manufacturing. A real multi-item Bill of Materials is built for Pump Assembly A1 (steel sheet, copper wire, ball bearings). A Production Plan pulls the Sales Order through ERPNext's own native MRP engine, which computes a genuine raw-material shortfall against Stock's existing baseline — not a fabricated number. A Work Order is raised and submitted, which automatically creates its own Job Card, logged with a real Time Log against a real employee.

Purchase. The MRP-generated Material Request is converted into a Purchase Order with a new supplier, SteelCraft Industries, walked through Purchase's own approval workflow. Goods Receipt deliberately includes a small rejected-quantity line (showing the automatic Rejected Warehouse default), and the Purchase Invoice carries a deliberate rate deviation — automatically flagged by the 3-way match check, never blocked. A Payment Entry closes the loop.

Stock. A baseline raw-material receipt exists before any of this starts — deliberately modest, so the shortfall Manufacturing's MRP finds is real, not staged.

3 The Live Click-Path — Walking a Client Through It

Everything below is real, clickable, and already seeded. Open /app/project/PROJ-0025 and start here:

  1. Open the Project. Point out the PMO Approved workflow state, the Project Manager field, and the Key Risks Summary — this is a real project, not a demo shell.
  2. Scroll to Connections. This is the whole point: one native ERPNext tab, zero custom code, showing every module's real linked records grouped by type — Project (Task, Timesheet), Material (Material Request, BOM, Stock Entry), Sales (Sales Order), Purchase (Purchase Order, Receipt, Invoice), Manufacture (Work Order), Risk.
  3. Click Sales Order → show the real 250-unit order to Apex Manufacturing Co, submitted, tagged to this exact project.
  4. Click BOM → show the real multi-item bill of materials and its live costed total — not a placeholder.
  5. Click Work Order → open its Job Card from the Connections tab there too — show the real Time Log logged against a real employee.
  6. Click Material Request → explain this was not typed in by hand — it's the output of ERPNext's own MRP engine, run against the Sales Order, computing a genuine shortfall.
  7. Click Purchase Order → then its own Connections tab to reach the Goods Receipt and Purchase Invoice — point out the rejected-quantity line and the automatic 3-way match flag on the invoice (Flagged — rate 92.0 vs PO rate 85.0), both real built features, not staged for the demo.
  8. Close the loop back at the Project — every one of those documents is reachable from the single record you started at.

4 How This Was Built — Purely Data, Zero Code Changes

The connection mechanism is Project.project — a field ERPNext already ships on Sales Order, Purchase Order/Receipt/Invoice, Stock Entry, Work Order, Job Card, BOM, Payment Entry, and Expense Claim. Setting it consistently on every record is the entire trick; the Connections tab and its grouping already exist natively. Nothing was added to the schema, no new doctypes, no new hooks — this is a pure data-seeding exercise, one small script per app.

# Run once, in this exact order — each step depends on data the previous one creates 1. bench --site <site> execute scale_project_management.demo_project_seed.run 2. bench --site <site> execute scale_sales.demo_project_seed.run 3. bench --site <site> execute scale_stock.demo_project_seed.run 4. bench --site <site> execute scale_manufacturing.demo_project_seed.run 5. bench --site <site> execute scale_purchase.demo_project_seed.run

Every script is idempotent (safe to re-run), manual-invoke only (never wired into after_install/after_migrate — a fresh site migrating for the first time doesn't have the masters this assumes, the same reason every other demo seed in this codebase stays manual), and independently safe: each app commits only its own data at its own end, so one script failing partway can't corrupt another app's data. Shipped as its own small, separately-reviewable PR — feature/connected-demo-data — after the three new Supply Chain apps (Stock/Purchase/Manufacturing) land, since this depends on all of them existing.
