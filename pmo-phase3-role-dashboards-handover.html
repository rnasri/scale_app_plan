1. What This Delivers

Before this work, every logged-in user of Scale PMO — Administrator, Project Manager, or a regular Employee — saw the exact same dense, uniform Desk: the same Overview tiles, the same full Shortcuts/Cards list, the same tab bar, the same Project form. There was no role-shaped landing, no "my work" view, and no distinction between someone who owns the whole portfolio and someone who just needs to update one Task and log a few hours.

This track replaced that with three distinct, role-appropriate experiences — System Admin, Project Manager, and Employee / team member — built entirely on top of the existing Console/Workspace architecture (no parallel UI system, no new frontend framework). Two further personas, Consultant and Contractor, were explicitly parked by the owner and are not part of this delivery — see §6.

2. What Each Role Sees Now

System Admin / PMO Director Elevated

Unchanged from before, by design — the full Console tab bar (Overview, My Projects, My Work, Cockpit, Executive, Intelligence), the full Overview landing (Attention strip, 5 Position/Admin tiles, full Shortcuts list, all Cards), and the dense native Project form. Nothing was removed or hidden for this audience at any point in this track.

Project Manager Elevated

Same full navigation as Admin. Two things are new for this role specifically:

  • "My Projects" tab — a card grid of every Project they manage or are a team member on, RAG-coloured, with open/overdue Task counts. Clicking a Project they manage opens the existing Project form, now revamped for this role: the dense "PMO Kickoff & Governance" section defaults collapsed, one-click List/Kanban/Gantt Task-view shortcuts, and a "Quick-Add a Task" input.
  • If they're also a plain team member on a Project they don't manage, clicking that card instead opens the same lighter "Project Tasks" view an Employee gets (see below) — the PM/Team distinction is per-Project, not per-person.

Employee / Project team member Non-elevated

The most changed experience. On login, the Console tab bar shows only My Projects and My Work — Overview, Cockpit, Executive, and Intelligence are hidden. If they land on the Overview page anyway (e.g. via the sidebar), it's stripped down to just 4 relevant shortcuts (Project, Timesheet Entry (Mobile), Task Calendar, Project Library) — no Attention strip, no Admin tiles, no Cards.

  • My Projects — every Project they're a team member of (or manage), each tagged with a small PM/Team badge. Clicking a Project they're just a team member on opens Project Tasks: their own genuinely-assigned Tasks in green (status-editable), everyone else's Tasks on that Project in amber underneath, for context only.
  • My Work — every open Task actually assigned to them (native "Assign To" mechanism), across every Project, with inline status editing; a real weekly timesheet grid (Mon–Sun hours, submits one Timesheet); and a Quick Material Request form scoped to their own team's Projects.

3. Feature List — All Complete

Admin attention tiles DONE

5 KPI tiles on the Overview landing (High-Risk / At-Risk / On-Track Projects, Pending Approvals, Projects Missing a PM), styled to match scale_finance's native tile system exactly — same pastel-tint, icon-badge visual language used everywhere else in Scale Console. Each tile's click-through filters to exactly the Projects/Tasks that produced its own count — worth double-checking this stays true for any new tile added later, since it's easy for a tile's route filter to quietly drift from its count query (a real example: On-Track's click-through originally showed all active Projects instead of just the on-track ones, since "on-track" isn't a stored field on Project and needs its own explicit Project-name list rather than a simple status filter — see the full plan doc for detail). Pending Approvals is a special case worth knowing: it sums three different doctypes (Project Budget + Project Change Request + Timesheet), so a single click-through route can never show the full count — it opens a small pick-one breakdown dialog instead (see admin_attention_tiles.js's showBreakdownDialog). If you add a tile that also aggregates across multiple doctypes, use the same breakdown pattern on the backend rather than picking one doctype's route arbitrarily. This same fix was extended to the Attention strip chip too (the caption/count row above "Position") — that chip is plain native scale_console.js content (a bare <a href>, no route_options mechanism at all), so it's intercepted client-side in admin_attention_tiles.js rather than modifying the shared scale app. Worth knowing if you add a click interceptor anywhere else in this codebase: preventDefault() alone was not enough to stop the chip's native navigation — some other document-level click handler also processes the same click, so stopPropagation() + stopImmediatePropagation() were needed too.

"My Projects" — PM & team-member landing DONE

Card grid, RAG-coloured, PM-scoped stats strip with click-to-filter. Broadened mid-track to include plain team members, not just PMs — each card routes to either the full Project form or the new lighter "Project Tasks" view depending on the viewer's relationship to that specific Project.

"Project Tasks" — per-Project two-tier task view DONE

New page. Tasks genuinely assigned to the viewer (green, editable) versus everyone else's Tasks on that Project (amber, view-only) — split on real native Task assignment, not team membership or guesswork.

PM project-open revamp DONE

Role-conditional additions to the existing Project form for PMs only — Admin's form is byte-for-byte unchanged. Collapsed governance section, one-click Task-view shortcuts, Quick-Add a Task. Also fixed the pre-existing milestone RAG-on-Gantt colour bug while in this area.

Project/Task access scoped to team membership DONE

Backend permission work, not UI — team-member Employees are auto-granted scoped access to only the Projects/Tasks they're actually on (previously they had none at all). Prerequisite for everything else in this list actually being safe to ship.

"My Work" — Employee landing DONE

Assigned-Task list with inline status control, a genuinely new weekly timesheet grid (nothing like it exists natively in ERPNext/HRMS), and a scoped Quick Material Request form.

Console tab bar trimmed for non-elevated sessions DONE

Only My Projects and My Work show in the top nav for a plain Employee — Overview, Cockpit, Executive, Intelligence are hidden. Elevated roles see the full bar, unchanged.

Overview landing trimmed for non-elevated sessions DONE

Same audience, same reasoning — the Overview page itself (reachable via the sidebar regardless of the tab bar) is stripped to 4 relevant shortcuts, no Admin tiles, no Cards.

5. How This Was Verified

Every feature above was tested live against real seed data and, wherever possible, a genuinely authenticated non-admin session (Claude-in-Chrome sharing the same browser profile the owner had already logged in with — no credentials were ever typed by the assistant building this). Specific checks worth knowing about if you're picking this up:

  • Permission scoping was tested from both directions — a real team member correctly sees only their own Projects/Tasks, and a genuinely non-team-member Employee sees zero.
  • Elevated roles (System Manager, PMO Director, Projects Manager) were confirmed to see everything unrestricted, on both the tab bar and the Overview content, including after the trimming scripts run.
  • The weekly timesheet grid and Quick Material Request were confirmed to produce real, correctly-populated Timesheet and Material Request documents, not just a success toast.
  • Cross-page navigation within one browser session (not just fresh URL loads) was explicitly tested — this caught a real script-collision bug that only appeared that way (see the full plan doc for detail).

A clean bench migrate was run after every change; the branch diff against main is reviewed and audit-clean (no unrelated drift) as of this handover.

Gotcha worth knowing if you extend team_scope_hooks.py or write a similar permission_query_conditions hook: Frappe rewrites the table reference in your condition string when the doctype is reached via a dot-notation JOIN from another doctype (e.g. Task Calendar joining Project through Task's own project field) — but that rewrite only recognizes the fully backtick-quoted form, `tabDoctype`.`field`. Writing `tabDoctype`.field (column left bare) looks correct and works fine for a direct query on that doctype, but silently breaks the JOIN case with an "Unknown column" SQL error the moment some other view joins through it. Always backtick-quote both sides.
