What this plan is — and what it isn't

This is a clean-slate implementation blueprint produced by Claude Code for the Pixaflip × SIL engineering team. It is specific, technical, and opinionated. It answers the questions every developer and product lead needs before writing a single line of code:

  • Can Frappe/ERPNext actually support our 13-module plan at commercial scale?
  • How do we structure the codebase so multiple developers can work in parallel without stepping on each other?
  • When do we use Frappe OOTB, when do we extend it, and when do we build from scratch?
  • In exactly what order do we build, and what are the dependencies?

This plan is not a restatement of the AIWS Setup portal. It picks up where requirements end and engineering begins.

Scope note: This plan covers the ERP build only. The AIWS Intelligent Bridge (strategy alignment layer) is deferred by design — seams are kept open in the architecture but no Bridge code is built in this program. The ERP must be independently usable and sellable on its own.

Three non-negotiable principles

1 — Never fork. Always extend.

Zero modifications to Frappe, ERPNext, Frappe CRM, or Frappe HR source code. All customizations live in upgrade-safe custom apps using hooks, custom DocTypes, and fixtures.

A fork turns every upstream upgrade into a painful manual merge. Custom apps ride on top and survive upgrades cleanly.

2 — Configuration before code.

Before writing a single line of Python or JS, ask: can this be done with Custom Fields, Property Setters, Workflows, or Roles? Write code only when configuration is exhausted.

Config-level changes require no deployments, no tests, and no release cycles. They're also reversible.

3 — One module, one owner, one app.

Each business module maps to a custom Frappe app with a named team owner. Cross-module data flows through documented REST APIs or DocType links, never shared DB queries.

This prevents merge conflicts, enables different team speeds, and makes the product modular for customers.

Build waves — the delivery sequence

Wave 1 is three parallel tracks — not a single sequential track. Raghib (Sales + Marketing), Uday (Finance + Accounts), and Vandana (HR + PMO) all start on the same day. No track is more important or more foundational than another. The three tracks converge into Wave 2 when leads become available after their Wave 1 modules are done.

What Frappe/ERPNext gets us immediately

Before any custom work, a fresh ERPNext v15 install provides:

Data model

  • Customer, Supplier, Item masters
  • Lead, Opportunity, Quotation, Sales Order, Delivery Note, Sales Invoice
  • Purchase Order, GRN, Purchase Invoice
  • Stock Ledger, Warehouse, Batch, Serial No
  • Chart of Accounts, Journal Entries, Payment Entries
  • Employee, Leave, Attendance, Payroll

Infrastructure

  • Role-based permission engine
  • REST API auto-generated for every DocType
  • Webhook engine (outbound)
  • Background job queue (Redis/RQ)
  • Email integration (SMTP + POP3)
  • Notification engine (email, SMS, WhatsApp hooks)
  • Print format builder
  • Report builder (Query, Script)

Platform

  • Multi-tenant (site per client, shared bench)
  • Audit trail on every document
  • Workflow engine (approval chains)
  • Versioning on all DocTypes
  • Portal (customer/supplier self-service)
  • Full-text search
  • File attachments (local or S3)
