What it implements (verified against the code, not just the branch's own README)
  • Item Master import pipeline — converts SVE's raw client Item Master Excel into Frappe-ready sheets (scripts/convert_item_master.py), then imports them idempotently (scale_stock.item_master_import.run): 30 Item Groups and 2,516 Items created (site totals 44 groups / 2,794 items including pre-existing GrowSmart/demo data). Sales items get a placeholder HSN (999900) so India Compliance validation passes; / in item codes is rewritten to -; UOM is guessed from context since the source file carries none.
  • Project BOQ — a new two-doctype system (Project BOQ header, 19 fields; Project BOQ Line child table, 21 fields) that captures a client's BOQ Excel as quantities + descriptions only. Client Supply Rate / Amount are deliberately never imported — cost is derived from the Item's own buying rate or a linked BOM instead, not trusted from the client file.
  • Client Excel parser (scale_sales.boq_import.import_vconstruct) — reads the "High Side" / "Low Side" sheet structure the client's actual BOQ file uses, handles Excel's floating-point Sr. No. artifacts (1.2000000002 → text "1.2"), and turns description-only spec rows with no line number into standalone Note lines.
  • Item mapping (scale_sales.boq.auto_map_items) — exact code/name match, falling back to a unique substring match; every line is classified Mapped / Unmapped / Skipped, surfaced on the form via a live filter and a dedicated Mapped Items list.
  • Cost estimation (scale_sales.boq.refresh_estimates) — estimated_rate pulled from the Item's last purchase / buying price / valuation / standard rate, or from a linked BOM's total cost when one exists; estimated_amount = qty × rate, computed by Scale, never read from the client's own Rate/Amount columns.
  • Finalize / Approve workflow (scale_sales.boq.approve_boq) — for every mapped Supply/Buy line without a BOM, either links the Item's existing default submitted BOM or auto-creates and submits one from that line's mapped child components (a real "explode the kit" step, covered by its own test); locks quantities/descriptions and moves status to Approved. A Supply line with no component lines is deliberately left on plain Item rate rather than given an empty BOM.
  • Moved from PMO into Sales — the doctypes were originally being built inside scale_project_management and were relocated to scale_sales mid-build (so BOQ/quoting sits with the Sales team, not PMO) without renaming the doctypes, specifically to keep already-created records (e.g. BOQ-00265) intact across the move.
  • Permissions — Project BOQ access granted to Sales Manager, Sales User, and Projects Manager (full read/write), nobody else.
